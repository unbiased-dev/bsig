Reference Manual

React-like JSX, fine-grained signals, no Virtual DOM. Write plain {'{value}'} — the compiler makes it reactive.

Introduction

bsig is a Sigwork fork with one rule change: you never write () => in JSX. The Vite plugin wraps dynamic children and props into lazy getters at build time, so the runtime keeps its tiny fine-grained engine — signals connect directly to the DOM node or attribute that reads them.

Components are plain functions of one argument (props, with props.children). They run once. Nothing re-renders — only the anchor that depends on a changed signal updates.

Installation & Setup

Vite is required — the compiler is what removes the manual thunks. There is no buildless/CDN mode.

terminal
npm install
npm run dev     # demo at /
npm run build   # production bundle
bun test        # from the repo root (bun:test + happy-dom)
npm run typecheck
vite.config.js
import bsig from 'bsig/plugin';
export default {
  plugins: [bsig()],
};
src/main.jsx
import mount from 'bsig';
import App from './App.jsx';
mount(document.getElementById('app'), App);

signal()

signal<T>(value: T) → Signal<T> ({ value: T })

Basic reactive unit. Reads inside a dynamic zone subscribe; writes notify via microtask batch. Strict === equality — same value does not notify.

import { signal } from 'bsig';
const count = signal(0);
count.value;    // read
count.value = 5 // write
count.value++;  // works
const name = signal('world');
// plain JSX — plugin makes it live, no arrow needed
<p>Hello, {name.value}</p>

reactive()

reactive<T extends object>(obj: T) → T

Deep proxy with per-property subscriptions. Nested objects are cached (stable identity) and made reactive lazily.

import { reactive } from 'bsig';
const state = reactive({ user: { name: 'Ada' }, items: ['a'] });
<p>{state.user.name}</p>   // live, no arrow

computed()

computed<T>(fn: () => T) → ReadonlySignal<T>

Derived read-only signal. Recalculates when dependencies change.

const doubled = computed(() => count.value * 2);
<p>{doubled.value}</p>

scope()

scope(fn) → stop

Collects effects for bulk disposal. Used internally for components, dynamic zones, and list items — unmount stops everything, no leaks.

effect()

effect(fn, is_scope?) → stop

Runs immediately, re-runs on dependency change after running the previous cleanup. Dependencies are re-collected every run.

watch()

watch(signal | getter, (next, prev) => void) → stop

Like effect but skips the initial run — fires only on change.

untrack()

untrack(fn) → T

Reads signals without subscribing.

h() & JSX

h(tag | Component | null, props, ...children)

String tag creates a real element, function tag runs once as a component, null is a fragment. You write JSX; the plugin emits h() with thunks already inserted.

// source
<div class="card"><p>Hello, {name.value}</p></div>
// compiled (conceptual)
h("div", { class: "card" }, h("p", null, "Hello, ", () => name.value));

Props & Events

Write plain values. Dynamic props are auto-wrapped; on* and ref are never wrapped.

<button
  disabled={disabled.value}
  class={disabled.value ? 'opacity-50' : ''}
  onClick={() => disabled.value = !disabled.value}>
  {label.value}
</button>

Dynamic Children

Any expression container becomes a dynamic zone with an anchor. Ternaries, &&, and map() just work. Nodes are reused by identity; moves are patched, not recreated.

<p>{show.value ? 'visible' : 'hidden'}</p>
{show.value && <span>Appears!</span>}
<ul>{items.value.map(i => <li>{i}</li>)}</ul>

ref

Pass a signal (or callback). The element is assigned on render.

const el = signal(null);
onMount(() => el.value.focus());
<input ref={el} type="text" />

Creating Components

One argument: props. Children live on props.children. Parent callbacks are plain props — call props.onChange() directly, no emit.

function Counter(props) {
  const count = signal(props.start ?? 0);
  return (
    <div>
      <p>{count.value}</p>
      <button onClick={() => count.value++}>+</button>
    </div>
  );
}
<Counter start={10} />

children

React-like. Render {'{props.children}'} directly.

function Card(props) {
  return (
    <div class="card">
      {props.title && <h2>{props.title}</h2>}
      <div class="card-body">{props.children}</div>
    </div>
  );
}

onMount / onUnmount

Mount fires after insertion; unmount fires on conditional/list removal or app teardown. Register onUnmount inside onMount for resources that only exist after mount.

provide / inject

Context without prop drilling. Unchanged from Sigwork.

<Show>

Show({ when, fallback?, children })

Preferred conditional in JSX. when is auto-thunked by the plugin.

<Show when={show.value} fallback={<i>hidden</i>}>
  <b>visible</b>
</Show>

If()

If(cond-thunk, render-thunk, fallback?) — thunks required

Low-level helper. In .jsx prefer <Show> or plain ternaries; use If from plain JS where you control the thunks.

For()

For(signal | getter | array, key | null, (item, i) => Node)

Keyed list with node reuse. Pass the signal itself — no getter needed. Each item gets its own scope.

<ul>{For(todos, 'id', item => <li>{item.text}</li>)}</ul>
// unkeyed: For(todos, null, ...)
// derived: For(() => todos.value.filter(t => !t.done), 'id', ...)

<Transition>

Transition({ enter?, idle?, leave? }) — kept as-is

Single-child CSS transition via [active, from, to] arrays. Leave waits for transitionend before removal.

<Transition
  enter={['transition-all duration-300', 'opacity-0', 'opacity-100']}
  leave={['transition-all duration-200', 'opacity-100', 'opacity-0']}>
  <Show when={open.value}><div class="modal">Hi</div></Show>
</Transition>

<Component>

Component({ is, ...props })

Dynamic tag. is is stripped, remaining props (including children) forward. Reactive is remounts.

<Component is={() => views[route.value]} />

App Mounting

Mounts a root component, returns an unmount that stops all scopes, runs unmount hooks, and removes DOM. Fragment roots are supported.

const unmount = mount(document.getElementById('app'), App);
unmount(); // clean, no leaks

Vite Plugin

bsig/plugin runs before Vite transforms: JSX expression children and dynamic props become () => expr, then classic JSX compiles to h(). It also injects import { h } from "bsig" (relative to each file) when the file doesn't already import h — so JSX files never import h explicitly. Skips on*, ref, existing functions, and static literals. Override the runtime path with bsig({ runtime: "./path/to/runtime.js" }).

TypeScript & Tests

src/runtime.d.ts gives signal generics and component prop checking; npm run typecheck validates src/typecheck/smoke.tsx. bun test runs the happy-dom suite: text/prop reactivity without element rerender, computed, children, conditionals, Show, keyed For moves, fragment mount/unmount, thunk-only If, lifecycle ordering, unmount leak checks, provide/inject, watch/untrack/scope, reactive arrays, refs, SVG, dynamic Component switching, a 60-step seeded list-conformance fuzz, adjacent-swap move counting, and Transition enter/leave timing — plus compiler transform and tree-shake guards.

Known Limitations

Vite required. Plain h() without the plugin needs manual thunks again.

Transition leave is not reversible mid-exit — same as Sigwork.

Shared HTML/SVG tag names inside SVG trees resolve to HTML namespace — same as Sigwork.

bsig — better Sigwork. Signals, no VDOM, React-like JSX.
